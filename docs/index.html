The pipeline is the product.

Nothing ships from a laptop. Every release passes through the same four gates, automatically, before a human ever clicks merge.

cron · 6h
Upstream poll

A scheduled workflow watches TDLib master every 6 hours and triggers on change.

docker · 4x
Matrix build

All 4 native architectures compile in parallel with a pinned NDK r27c.

gate
Binary verification

ELF headers are validated with readelf -h, never by file size. Partial ABI sets are rejected.

PR → merge
Human review, then publish

An automated PR carries the full diff plus SHA-256 checksums. Merging publishes signed AARs straight to Maven Central.

What's in the box

:core

tdjson + TdApi, packaged

Four ABIs of libtdjson.so with TdApi.java, Client.java and R8 consumer rules shipped inside the AAR itself.

:ktx

Coroutines wrapper

Updates as Flow<TdApi.Update>. Thin bridge, ~150 lines, no app logic.

ci

Upstream auto-update

Version bumps land as review-ready PRs with diff and checksums. You never chase TDLib releases.

compat

Android 15 ready

16KB page alignment verified per-build, forward compatible with target SDK 35.

:sample

Minimal working example

Clone, open, run. The shortest path from zero to a connected TDLib client.
